# Hui 阶段一需求管理清单

## 目标

本阶段目标不是重做 InvenTree，而是在尽量不改核心模型的前提下，完成“中文可用、Docker 可部署、样品/库存流程可落地”的最小闭环。

## 中文与国际化核验

- 已支持国际化：后端使用 Django i18n，前端使用 Lingui。
- 已内置简体中文：后端存在 `src/backend/InvenTree/locale/zh_Hans`，前端存在 `src/frontend/src/locales/zh_Hans`。
- 本 fork 已将 Docker 默认语言设置为 `zh-hans`，默认时区设置为 `Asia/Shanghai`。

## 需求映射清单

| 需求 | 当前方案 | 状态 | 备注 |
| --- | --- | --- | --- |
| 产品名称 | 使用 `Part.name` | 已支持 | 原生字段 |
| 产品图片 / 样品照片 | 使用 `Part.image` | 已支持 | 主图即样品图，不单独拆附件流程 |
| 产品（样品）初次到店时间 | 使用 Part 参数 | 一期落地 | 建议参数名：`样品初次到店时间` |
| 大货到店时间 / 到货库存数量 | 使用 Stock Item + Stock Tracking | 已支持 | 每次入库都会记录历史 |
| 每次进出库记录 | 使用 Stock Tracking | 已支持 | 自动记录数量变化、时间、操作人 |
| 出库原因可选 | 先用备注规范落地 | 一期落地 | 统一使用：`内部购买 / 抖店销售 / 视频号销售 / 样品外借` |
| 出入库备注 | 使用库存操作 `notes` | 已支持 | 可搜索、可追溯 |
| 产品价格 | 使用 Part 参数 | 一期落地 | 建议参数名：`销售单价` |
| 抖店上架数量 | 使用 Part 参数 | 一期落地 | 建议参数名：`抖店上架数量` |
| 视频号上架数量 | 使用 Part 参数 | 一期落地 | 建议参数名：`视频号上架数量` |
| 用户账号与密码 | 使用 Django 用户体系 | 已支持 | 原生登录认证 |
| 每人操作留痕 | 使用 Stock Tracking + 系统创建/更新时间 | 部分支持 | 库存动作已完整记录用户与时间 |
| 普通用户不可随意删除 | 使用 Group / Role 权限 | 已支持 | 不授予 `delete` 权限即可 |
| 仅超级管理员可删核心数据 | 使用 Superuser 与权限隔离 | 已支持 | 建议日常不用超管账号 |
| 开箱初始化 | 启动时自动 bootstrap | 一期落地 | 自动创建参数模板和默认用户组 |

## 一期实施约束

- 不修改 InvenTree 核心数据模型。
- 不新增全局业务菜单，不做大范围前端重构。
- 先通过“参数模板 + 主图 + 库存历史 + 权限分组 + 中文默认配置”完成上线。

## 一期验收标准

- Docker 部署后默认中文界面可用。
- Docker 启动后自动生成一期参数模板与默认用户组。
- 可创建商品、上传主图、录入样品类字段。
- 可执行入库/出库并查看每条库存历史的操作人、时间、备注。
- 可按用户组区分“仓储人员”和“普通员工”权限。
- 普通用户和仓储用户默认不具备删除核心数据权限。

## 二期候选

- 将“出库原因”从备注规范升级为下拉枚举。
- 提供面向直播/电商场景的专用商品录入页面。
- 对关键删除动作补充更强的审计展示页。
